# Отчет по результатам работы Агентов (Модуль А)

## 1. Описание реализованного функционала

В ходе работы были реализованы следующие агенты для сбора, обогащения и анализа данных:
* **Агент 1.1 (Загрузка данных и генерация карт):** Скрипт загружает данные из конфигурационного CSV-файла в базу данных PostgreSQL. Дополнительно по геокоординатам (широта/долгота) автоматически генерируются изображения маршрутов (треков) с векторной картой OpenStreetMap (через библиотеку `contextily`).
* **Агент 1.2 (Сбор окружения):** Для каждой точки (или участка) трека производится запрос к Overpass API. Скрипт определяет тип местности в радиусе 500 метров (наличие леса, водоемов, поселков, жилых зон). Данные кешируются для избежания блокировок со стороны API и затем обновляются в базе данных в новом столбце `environment_type`.
* **Агент 1.3 и 1.4 (Анализ и предобработка):**
  - **Оценка важности факторов:** С помощью модели `RandomForestRegressor` и библиотеки `SHAP` производится анализ важности числовых признаков, влияющих на частоту шагов (`step_frequency`).
  - **Корреляционный анализ:** Строится тепловая матрица корреляций.
  - **Проверка на нормальность:** Формируется Q-Q plot (квантильный график) и гистограмма для оценки распределения переменной `elevation` (высоты).
* **Агент 1.5 (Аугментация):** Реализовано расширение набора изображений маршрутов методами компьютерного зрения. С помощью пакета `albumentations` применяются случайные преобразования (отражение по горизонтали, изменения яркости/контраста, сдвиг, повороты и RGB-shift), создавая по 3 новых варианта для каждой картинки трека.

## 2. Обоснование подходов к сбору и предобработке

1. **Использование PostgreSQL + pg8000:** В качестве базы данных была выбрана реляционная СУБД PostgreSQL, что обеспечивает надежность хранения. Для обхода системных конфликтов C-библиотек (DLL) на ОС Windows при работе с `psycopg2` был использован pure-python драйвер `pg8000`. Метод сохранения через `pandas.to_sql` позволяет сократить объём шаблонного кода.
2. **Оптимизация гео-запросов (Overpass):** API Overpass имеет строгие лимиты. Для обогащения данных координаты кластеризуются путем округления широты и долготы до 3 знаков (шаг сетки около 110 метров). Запрос делается только для уникальных ячеек сетки, а результаты сохраняются в локальный кэш-словарь, что радикально сокращает нагрузку на внешний сервер.
3. **Объяснимое машинное обучение (XAI):** Применение библиотеки `SHAP` позволяет не просто оценить "важность" признаков как в черном ящике, но и понять направление и силу влияния каждого отдельного значения на целевую переменную.

## 4. Структура базы данных и форматы файлов

**Итоговые форматы данных:**
- **Изображения:** `.png` (растровые графики отчетов и карты).
- **База Данных:** PostgreSQL (таблица `track_points`).
- **Скрипты агентов:** `.py` (Python 3.9).

**Структура таблицы `track_points` в базе данных:**
- `track_id` (INTEGER) — Идентификатор поездки/маршрута.
- `point_id` (INTEGER) — ID конкретной точки (снимка состояния).
- `latitude` (FLOAT) — Широта.
- `longitude` (FLOAT) — Долгота.
- `elevation` (FLOAT) — Высота над уровнем моря.
- `datetime` (TEXT) — Временная метка.
- `data` (TEXT) — Дополнительный маркер даты.
- `temp` (FLOAT) — Температура.
- `water_counts` / `vegetation_counts` (INTEGER) — Показатели окружения.
- `distance` (FLOAT) — Дистанция.
- `speed` (FLOAT) — Скорость в моменте.
- `step_frequency` (FLOAT) — Частота шагов (целевая переменная).
- `region` (TEXT) — Название региона ("Тюрингия" и др.).
- `map_image_path` (TEXT) — Локальный путь до карты (вычислен агентом 1.1).
- `environment_type` (TEXT) — Тип местности, полученный из Overpass (вычислен агентом 1.2).
