# Программная документация: Умный атлас туриста (Модуль Г)

## 1. Введение
Данная документация описывает архитектуру, интерфейсы и инструкции по запуску аналитической Геоинформационной системы туристических рисков (Задание 4.3). Система базируется на микросервисной архитектуре и состоит из API-сервера предсказаний (FastAPI) и клиентского графического интерфейса (Streamlit).

## 2. Инструкция по запуску и справка по командам

### Требования
* ОС: Windows / Linux / macOS
* Python 3.9+ 
* Установленный СУБД PostgreSQL (БД `tourism_data`)
* Необходимые библиотеки: `pip install fastapi uvicorn pydantic joblib pandas streamlit plotly`

### Этап 1. Запуск сервера API
API-Сервис предоставляет доступ ко всем обученным моделям (RandomForestClassifier).
1. Откройте окно терминала.
2. Запустите сервис через ASGI сервер Uvicorn:
   ```bash
   uvicorn agent_4_1_api:app --host 127.0.0.1 --port 8000
   ```
3. Сервер будет доступен по адресу `http://127.0.0.1:8000`. 
Панель разработчика с интерактивным тестированием (Swagger UI) доступна по адресу `http://127.0.0.1:8000/docs`. Обратите внимание, консоль должна оставаться открытой для работы сервера в фоновом режиме.

### Этап 2. Запуск Клиентского Приложения
Для загрузки графического дашборда с интерактивной картой местности:
1. Откройте **новый** (второй) терминал.
2. Выполните запуск клиента:
   ```bash
   streamlit run agent_4_2_app.py
   ```
3. Приложение автоматически откроется в браузере (обычно по адресу `http://localhost:8501`).

## 3. Описание API Эндпоинтов

### Основной эндпоинт: `POST /predict_risk`

**Описание:** 
Принимает географические и погодные параметры планируемого маршрута и возвращает категорию риска, а также математическую уверенность ИИ-модели.
* Уровень `0`: Участок безопасен.
* Уровень `1`: Средний риск (весенние паводки, низменности, тяжелая эвакуация).
* Уровень `2`: Критический риск (летняя пожароопасность).

**URL:** `http://127.0.0.1:8000/predict_risk`  
**HTTP Метод:** `POST`  
**Headers:** `Content-Type: application/json`

#### Формат запроса (Request Body JSON)
В теле запроса ожидается JSON-структура со следующими обязательными полями:

```json
{
  "elevation": 500.0,
  "temp": 25.5,
  "speed": 1.2,
  "distance": 15.0,
  "water_counts": 2.0,
  "vegetation_counts": 8.0,
  "month": 7
}
```

* `elevation` (float) - Текущая высота над уровнем моря (м).
* `temp` (float) - Ожидаемая температура среды (°C).
* `speed` (float) - Предполагаемая средняя скорость движения туриста (м/с).
* `distance` (float) - Пройденная дистанция (км) от старта (важно для эвакуации).
* `water_counts` (float) - Наличие водоемов в радиусе 500м.
* `vegetation_counts` (float) - Уровень флоры / лесного массива.
* `month` (int) - Порядковый номер месяца (1 - 12). 

#### Формат ответа (Response JSON) - Успех (200 OK)

```json
{
  "status": "success",
  "risk_cluster": 2,
  "confidence": 0.84,
  "message": "Прогноз успешно построен."
}
```
*Где `confidence: 0.84` означает уверенность нейросети в прогнозе на 84%.*

#### Возможные коды ошибок

* **422 Validation Error**: Отправлены неверные типы данных (например, текст вместо числа в body).
* **500 Internal Server Error**: Возникает, если `risk_classifier.pkl` отсутствует в папке `models/`. Серверу нечего загружать. Нужно запустить Модуль 3 (`agent_3_1_modeling.py`).

## 4. Примеры использования (Интеграция сторонних систем)

Разработчики сторонних мобильных приложений (Android/iOS) могут внедрять оценку рисков в свои навигаторы через стандартные HTTP запросы.

**Bash (cURL) - Пример запроса в разгар августа к высокой лесной зоне:**
```bash
curl -X POST "http://127.0.0.1:8000/predict_risk" \
     -H "Content-Type: application/json" \
     -d '{
           "elevation": 2500.0,
           "temp": 30.0,
           "speed": 1.1,
           "distance": 22.0,
           "water_counts": 1.0,
           "vegetation_counts": 9.0,
           "month": 8
         }'
```
